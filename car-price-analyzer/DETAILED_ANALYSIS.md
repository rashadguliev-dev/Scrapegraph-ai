# 🕵️‍♂️ Детальный Аудит Проекта Car Price Analyzer

Этот документ содержит детальный анализ архитектуры, кода, производительности и надежности проекта `car-price-analyzer`.

## 1. 🏗 Архитектура и Логика

### ✅ Сильные стороны
*   **Четкое разделение:** Backend (FastAPI) и Frontend (HTML/JS) разделены логически.
*   **Асинхронность:** Использование `asyncio` и `aiohttp` для неблокирующего I/O.
*   **Параллелизм:** Скрейпинг выполняется параллельно (`asyncio.gather`), что значительно ускоряет работу.
*   **Изоляция блокирующего кода:** Вызовы `SmartScraperGraph` (синхронные) правильно обернуты в `run_in_executor`.

### ⚠️ Проблемы и Риски
*   **Масштабируемость:** Запуск 19 задач одновременно (`ALL_SITES_CONFIG`) может привести к исчерпанию лимитов API Gemini (Rate Limits) или блокировке IP со стороны целевых сайтов. (Исправлено: добавлен Semaphore(4)).
*   **Зависимость от LLM:** Вся логика извлечения данных полагается на способность Gemini вернуть корректный JSON. Если формат ответа изменится или модель "галюцинирует", парсинг сломается.

## 2. 💻 Качество Кода

### 🔍 Найденные проблемы

#### 1. Неиспользуемый код (Dead Code)
*   **Файл:** `backend/scraper.py`
*   **Проблема:** Функция `scrape_with_crawl4ai` определена, но закомментирована.
*   **Решение:** Удалить для чистоты кода или раскомментировать и использовать как fallback.

#### 2. Хрупкий парсинг данных
*   **Файл:** `backend/main.py`
*   **Проблема:** Парсинг года (`car.get('year')`) не валидируется. Если LLM вернет "2022 model", это может вызвать ошибку в UI или расчетах.
*   **Решение:** Добавить функцию `clean_year` (по аналогии с `clean_price`).

#### 3. Дублирование логики
*   **Файл:** `backend/telegram_bot.py`
*   **Проблема:** Пересчет `uae_avg_usd` внутри бота, хотя это значение уже вычисляется в `main.py` и используется для расчета прибыли.
*   **Решение:** Передавать `uae_avg` в функцию отправки отчета или использовать уже рассчитанные данные из `results`.

#### 4. Хардкод финансовых данных
*   **Файл:** `backend/calculator.py`
*   **Проблема:** Курсы валют (`EXCHANGE_RATES`) и стоимость доставки (`SHIPPING_COSTS`) жестко прописаны.
*   **Риск:** Данные быстро устареют.
*   **Решение:** В будущем добавить API для получения актуальных курсов.

## 3. 🚀 Производительность и Надежность

### 🔴 Критическая проблема: Rate Limiting (Исправлено)
*   **Описание:** Ранее запускалось 19 одновременных запросов.
*   **Исправление:** Внедрен `asyncio.Semaphore(4)`.

### 🟡 Ресурсоемкость
*   **Описание:** `SmartScraperGraph` может быть ресурсоемким.
*   **Решение:** Семафор ограничивает одновременную нагрузку.

## 4. 🔒 Безопасность

*   **XSS Risk (Frontend):** Вставка данных через `innerHTML` в `app.js` (например, `car.site` или `car.model`). Хотя данные приходят с бэкенда (из LLM), теоретически LLM может вернуть вредоносный скрипт, если он был на сайте.
*   **Решение:** Использовать `textContent` или экранирование.
