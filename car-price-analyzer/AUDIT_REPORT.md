# 🕵️‍♂️ Детальный Аудит Проекта Car Price Analyzer

Этот документ содержит детальный анализ архитектуры, кода, производительности и надежности проекта `car-price-analyzer`.

## 1. 🏗 Архитектура и Логика

### ✅ Сильные стороны
*   **Четкое разделение:** Backend (FastAPI) и Frontend (HTML/JS) разделены логически.
*   **Асинхронность:** Использование `asyncio` и `aiohttp` для неблокирующего I/O.
*   **Параллелизм:** Скрейпинг выполняется параллельно (`asyncio.gather`), что значительно ускоряет работу.
*   **Изоляция блокирующего кода:** Вызовы `SmartScraperGraph` (синхронные) правильно обернуты в `run_in_executor`.

### ⚠️ Проблемы и Риски
*   **Масштабируемость:** Запуск 19 задач одновременно (`ALL_SITES_CONFIG`) может привести к исчерпанию лимитов API Gemini (Rate Limits) или блокировке IP со стороны целевых сайтов.
*   **Зависимость от LLM:** Вся логика извлечения данных полагается на способность Gemini вернуть корректный JSON. Если формат ответа изменится или модель "галюцинирует", парсинг сломается.

## 2. 💻 Качество Кода

### 🔍 Найденные проблемы

#### 1. Неиспользуемый код (Dead Code)
*   **Файл:** `backend/scraper.py`
*   **Проблема:** Функция `scrape_with_crawl4ai` определена, но закомментирована в `get_car_prices`. Проект не использует Crawl4AI, хотя это было в ТЗ.
*   **Решение:** Интегрировать Crawl4AI как запасной вариант или удалить, если ScrapeGraphAI справляется.

#### 2. Хрупкий парсинг цен
*   **Файл:** `backend/main.py`
*   **Код:** `price_clean = ''.join(c for c in price_raw if c.isdigit() or c == '.')`
*   **Проблема:** Этот код некорректно обработает европейские форматы цен (напр., `20.000` станет `20000.0`, но `20.000,00` может стать `20000.00` или вызвать ошибку при конвертации). Форматы `20 000` (с пробелом) обрабатываются корректно, но `1,200` (запятая) просто теряет запятую, что ок для `1200`, но опасно для `1,200.50` -> `1200.50`.
*   **Решение:** Использовать Regex для более надежного извлечения чисел или просить LLM возвращать строго `float`.

#### 3. Хардкод финансовых данных
*   **Файл:** `backend/calculator.py`
*   **Проблема:** Курсы валют (`EXCHANGE_RATES`) и стоимость доставки (`SHIPPING_COSTS`) жестко прописаны.
*   **Риск:** Данные быстро устареют.
*   **Решение:** В будущем добавить API для получения актуальных курсов.

#### 4. Обработка ошибок
*   **Файл:** `backend/scraper.py`
*   **Проблема:** При ошибке возвращается `None` или словарь с ключом `error`. Это обрабатывается в `main.py`, но теряется детальный контекст ошибки для отладки.
*   **Решение:** Использовать кастомные исключения.

## 3. 🚀 Производительность и Надежность

### 🔴 Критическая проблема: Rate Limiting
*   **Описание:** `asyncio.gather(*tasks)` запускает запросы ко всем 19 сайтам одновременно. Каждый запрос создает экземпляр `SmartScraperGraph`, который делает запрос к API Gemini.
*   **Риск:** Бесплатный и даже платный тиры Gemini API имеют ограничения (RPM - Requests Per Minute). 19 одновременных запросов с высокой вероятностью вызовут ошибку `429 Too Many Requests`.
*   **Решение:** Внедрить `asyncio.Semaphore` для ограничения количества одновременных запросов (например, до 3-5).

### 🟡 Ресурсоемкость
*   **Описание:** `SmartScraperGraph` может запускать headless браузер (Playwright) под капотом. 19 браузеров одновременно "съедят" всю RAM на локальной машине.
*   **Решение:** Семафор также решит эту проблему.

## 4. 🔒 Безопасность

*   **CORS:** Разрешены все источники (`allow_origins=["*"]`). Для локального запуска это нормально, но для продакшена недопустимо.
*   **API Keys:** Ключи читаются из `.env`, что правильно. Логирование ошибок настроено, важно следить, чтобы ключи не попали в логи (сейчас вроде чисто).
